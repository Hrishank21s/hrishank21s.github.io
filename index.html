01

Live in production · Club management SaaS

TableTracker

The floor console a snooker and pool club runs on every day: live tables, exact billing, customer ledger and online booking.

What it does

  • Live board of every table with running timer and bill; the bill freezes the instant staff clicks Stop
  • Customer ledger with prepaid wallet, dues and Gold-style membership discounts
  • Public availability board, online booking flow and self-service balance lookup
  • Admin tools: users per floor, analytics, audit log and CSV exports
Visit the live club site ↗

How it works

  1. 1

    Staff start a session

    Pick a table, optionally attach a customer; the timer and rate are locked in.

  2. 2

    Time and items bill live

    Exact proportional time plus refreshments, discounts applied automatically.

  3. 3

    Settle and record

    Cash, online or wallet; the ledger, dues and analytics update at once.

Specifications

Runtime
TypeScript on Cloudflare Workers (Hono)
Database
Cloudflare D1 (SQLite), additive migrations
Auth
scrypt password hashes, HMAC-signed sessions, CSRF tokens
Money
Integer paise, exact proportional billing, no minimum charge
Tests
Vitest inside the Workers runtime
Rewrite
Ported from Python/Pyodide with a parity harness against the original

02

Live in production · QR ordering + kitchen app

Weekend Rush Café

Guests scan a floor QR, order and pay; the chef's phone rings until the order is started; the owner sees exact sales.

What it does

  • Mobile QR menu per floor (62 items, categories, cart) with Cashfree checkout
  • Chef dashboard (PWA) and a native Android app that rings until START is tapped
  • Owner dashboard: daily and monthly sales, best sellers, refunds, users, kitchen on/off
  • Paid orders are immutable and reports use the IST business day
Staff app downloads ↗

How it works

  1. 1

    Scan and order

    Each floor has its own QR; guests pick items and enter a name.

  2. 2

    Pay, then confirm

    An order becomes paid only after Cashfree's own API confirms the payment.

  3. 3

    Kitchen rings

    The chef gets a push and a ringing alert; tapping START stops it.

Specifications

Runtime
Hono Worker + D1 + React/Vite PWA, one deployment
Payments
Cashfree PG, server-side settlement check
Push
Own VAPID keys, RFC 8291 on WebCrypto
Android
Native Kotlin app, watches the kitchen list, no Firebase account needed
Integrity
Paid orders and items locked by DB triggers; money in integer paise
Quality
141 automated tests on real D1 migrations; runs on the Cloudflare free tier

04

Open source · MIT · AI agent platform

AgentOS

A self-hosted team of AI agents for macOS, with approvals, memory and automations, and the OpenCode CLI as a swappable brain.

What it does

  • Multi-agent runtime with per-agent prompts, models, permissions and timeouts
  • Approval engine: risky commands (sudo, rm, dd and friends) always wait for a human
  • Long-term memory with full-text search, projects, notes and chat
  • Cron and interval automations, crash recovery and a real-time dashboard
View source on GitHub ↗

How it works

  1. 1

    Queue a task

    Priority queue with concurrency limits, progress logs and cancel/retry.

  2. 2

    Compose the prompt

    Agent instructions, project context, notes and relevant memories.

  3. 3

    Run and audit

    The brain executes; approvals, output and logs stream to the dashboard.

Specifications

Backend
Fastify + TypeScript, SQLite (FTS5)
Frontend
React 18 + Vite, server-sent events
Security
scrypt (N=65536), lockout, rate limits, no shell execution
Execution
spawn with argv only, shell disabled
Quality
109 tests
